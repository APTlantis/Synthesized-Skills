# Generator contracts and a minimal fixture

| Tool | Good fit | Native/config boundary to inspect |
|---|---|---|
| Astro Starlight | Content-driven Astro docs | Astro integration/content schema, configured or autogenerated sidebar, default search behavior; confirm built Pagefind assets |
| Docusaurus | React/MDX docs with release versions | Docs plugin, sidebars, route base, version snapshots; third-party search needs its own configuration |
| MkDocs | Python-oriented Markdown docs | `mkdocs.yml`, `docs_dir`, explicit `nav`, plugins; replacing `plugins` must retain search if required |
| Material for MkDocs | MkDocs with theme UI/search enhancements | Theme and extensions are additional dependencies; verify feature availability in the installed edition/version |
| Asciidoctor | Transform AsciiDoc documents | It is a processor, not by itself a complete versioned documentation portal |
| Antora | Component/versioned AsciiDoc documentation | Playbook, component descriptors, modules and navigation; distinct toolchain from standalone Asciidoctor |

Minimal MkDocs fixture (use an owned disposable folder):

```yaml
site_name: Fixture Docs
site_url: https://example.invalid/docs/
nav:
  - Home: index.md
  - Guide: guide.md
plugins:
  - search
```

Create `docs/index.md` with a relative `guide.md` link and `![fixture](assets/pixel.png)`, and `docs/guide.md` with a fenced code block and return link. Run `python -m mkdocs build --strict`; inspect generated HTML and `search/search_index.json` in the actual output. This recipe requires MkDocs; a missing module is a skip, not a successful build. Review strict warnings rather than disabling them blindly.

For Starlight/Docusaurus use the repository's pinned package script, commonly `pnpm build`, rather than assuming a universal scaffold command. Verify the actual build script before running it. Development servers do not prove search or static route behavior. For AsciiDoc test includes, attributes, xrefs and source highlighting with the selected publisher; do not feed it Markdown frontmatter as if native.

Release acceptance: inspect output titles/canonical metadata, description/social cards where needed, root and subpath assets, external search credential boundaries, redirects and old inbound links. Link-check fixtures include anchors, percent encoding, Unicode filenames and case mismatches. Keep source editable and publishing separate from build verification.
